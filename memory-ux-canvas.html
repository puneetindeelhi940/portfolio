The Memory UX Canvas

A worksheet for deciding what an AI should remember, what it should let go of, and what it has no business storing without asking.

Every product now wants to ‘remember’ the user. Almost none of them decide, on purpose, what to remember, what to let go of, and what they have no business storing at all.

So they land in one of two failure modes: forget everything and feel dumb, or remember everything and feel like surveillance. The line between the two isn’t technical. It’s a design decision that usually never gets made. The canvas is where you make it — before you write a line of code.

01

The problem

Memory is the fastest way to make an AI feel personal. It’s also the fastest way to make it feel creepy. Same mechanism, opposite outcome.

Teams reach for ‘store the whole history’ because it’s the easy default. Then they’re surprised when a user feels watched, or when the model drags up something from four months ago that was never meant to last. The problem isn’t too much memory or too little. It’s memory nobody designed.

02

The model

The canvas has three rows — Capture, Retain, Surface — and three columns you fill in for each: What, Why, and the Guardrail.

You work a piece of memory left to right, top to bottom. If you can’t fill the Guardrail cell, it doesn’t get stored. That one rule kills most of the trouble before it starts.

Three rows × three columns. A blank Guardrail cell means it doesn't get stored.
03

Principles

  1. Forgetting is a feature

    Decide the half-life before you decide the schema. Data with no expiry is a liability with no expiry.

  2. Recency over totality

    The last thirty days usually beat the last three years. Weight for it.

  3. Show your work

    If the user can’t see what you remembered, you haven’t earned the right to remember it.

  4. Ask before anything expensive to be wrong about

    Health, money, identity — those need a yes, not an inference.

  5. Every stored thing needs an off switch

    And the user has to be able to find it without a support ticket.

04

How I use it

Reach for it at the start of any feature that personalises — before the data model, not after.

Run one row per kind of memory: stated preferences, observed behaviour, hard facts. Fill every column, and refuse to leave the Guardrail blank. If a cell stays empty, that’s not memory — it’s a liability you haven’t noticed yet.
